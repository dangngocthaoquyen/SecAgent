## 4. Shared operation and reproducibility

The generic route remains **TestCase → target adapter → Runner → observer/evidence → deterministic evaluator → shared HybridEvaluator/Pi when eligible → VerdictResolver → Native Report** (`backend/src/testing/runner.py:68-145,179-211`; `backend/src/testing/evaluation_config.py:58-99`). DVAA-specific receipt parsing is confined to the replaceable collector/observer (`backend/src/observers/action_evidence_collector.py:8-26`, `dvaa_instrumented_receipt_collector.py:19-80`). No DVAA condition was added to generic Runner, HybridEvaluator, VerdictResolver or reporting in this acceptance.

One operator-owned file, `%LOCALAPPDATA%\SecAgent\asi03-judge.json`, currently has `mode=hybrid`, `judge_enabled=true`, `allow_live_judge=true`, `max_judge_calls=1`, provider `deepseek`, model `deepseek-v4-flash`, and an available Pi executable. The filename is historical; the contents use generic `RunnerEvaluationConfig` (`backend/src/testing/evaluation_config.py:17-99`). **The configured credential is absent in this audit shell**; only presence was checked. The successful ASI03 live artifact demonstrates a different operator process completed one Pi call. Do not start a new live Judge from this shell until the configured credential is present in the operator process. No credential value was read into this report.

Existing common launcher modes, after operator authorization and target/policy/dataset binding review:

```powershell
# Rule-only controlled ASI01 baseline/attack batch; no external Judge needed.
python start_secagent_local.py --enable-asi01-batch

# Shared Pi config for ASI01 ambiguity or reviewed imported ASI03/ASI05 response cases.
# Requires the configured credential in this operator process.
python start_secagent_local.py --enable-asi01-batch --judge-config "$env:LOCALAPPDATA\SecAgent\asi03-judge.json"
python start_secagent_local.py --enable-custom-imported-batch --enable-imported-live-local --judge-config "$env:LOCALAPPDATA\SecAgent\asi03-judge.json"
```

The launcher/preflight and API load one shared config, then each case receives a bounded Runner budget (`start_secagent_local.py:95-114,157-185`; `backend/src/workflow/api.py:1107-1152`; `backend/src/testing/evaluation_config.py:39-99`). Case selection still needs reviewed scope, target revision, dataset hash, complete observation and safe disclosure. The ASI01 controlled service admits only its pinned text cases and one request per case; it is not a four-ASI production batch. The action collector is presently injected through the explicit lab pilot entry point, not a general official batch workflow.
